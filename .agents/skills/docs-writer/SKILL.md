# Documentation Writer

Enforces Google and developer documentation standards for technical accuracy, structure, and readability.

## Guidelines

1. **Voice & Tone**:
   - Address the reader directly as "you".
   - Use active voice and present tense ("This command builds the binary", not "The binary will be built").
2. **Structure**:
   - Action-oriented headings (e.g. "Install dependencies", "Configure MCP servers").
   - Code blocks with explicit syntax highlighting labels (`bash`, `json`, `typescript`).
3. **Consistency**:
   - Keep command snippets minimal, copy-pasteable, and verifiable.
   - Cross-link related documentation and configuration options.
